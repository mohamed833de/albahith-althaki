# ربط Cloudflare بـ Shamela Link

## الحالة
هذا الملف يوثق إعداد الربط؛ لا تعتبر واجهة البحث متصلة حتى ينجح اختبار MCP فعليًا.

## نقطة الاتصال
- MCP endpoint: https://shamela.link/mcp
- المصادقة: OAuth، وفق دليل Shamela Link.
- لا تضع كلمات مرور أو OAuth tokens في ملفات المستودع أو الواجهة الأمامية.

## لماذا لا نستخدم fetch عاديًا من الصفحة؟
يجب أن يتم الاتصال من جهة الخادم، لأن المصادقة والرموز لا يجوز كشفها للزائر. كما أن MCP ليس REST endpoint عاديًا؛ يحتاج العميل إلى تهيئة جلسة JSON-RPC، واكتشاف الأدوات، ثم استدعائها وفق البروتوكول.

## مسار التنفيذ الآمن
1. استخدام Cloudflare Worker/Agent كجهة خادم.
2. إنشاء اتصال MCP إلى https://shamela.link/mcp مع OAuth مدعومًا وتخزين بيانات التفويض في تخزين الخادم الآمن.
3. تمرير طلب البحث فقط من واجهة الموقع إلى Worker.
4. تقييد الطلبات واحترام حدود Shamela Link، وعدم تنزيل المكتبة أو تجاوز الحدود.
5. إرجاع النصوص والبيانات المرجعية فقط، مع التعامل الواضح مع أخطاء المصادقة وحدود الخدمة.
6. اختبار التهيئة، وقائمة الأدوات، ثم بحث حقيقي قبل إزالة تنبيه «نسخة أولية».

## ملاحظة مهمة
دليل Shamela Link يشرح تسجيل الدخول عبر OAuth لعملاء MCP مثل Hermes. لا يكفي وحده لإثبات أن تدفق OAuth نفسه يعمل في Worker مخصص؛ يجب التحقق من تدفق التفويض/تجديد الرموز الذي يدعمه الخادم قبل تفعيل البحث. لا تستخدم رمزًا من جلسة ChatGPT، ولا تطلب من المستخدم إرسال بيانات الدخول في المحادثة.
